# Adeptio Live Status Dashboard — v1.2.1 Addendum (Pay Bill · 7-Day · Site Structure)

Companion to the **v1.2 Build Spec & Reuse Blueprint**. That document stays the base; this addendum records everything v1.2.1 adds. Two build products, one source of truth:

- `adeptio_paybill_dashboard_site/` — **the source of truth**: one set of website structure, data generated out as separate per-day log files.
- `adeptio_paybill_live_dashboard.html` — single-file build product (~72 KB; seeded replay inside, day logs deliberately not embedded), regenerated by `build_singlefile.py`. Use it for chat/artifact/gallery contexts that need one file.

## 1 · Engine changes (v1.2 → v1.2.1) — the complete list

| # | Change | Detail |
|---|---|---|
| E1 | **7-day timebase** | `const N=2016, STEP_MIN=5, DAY=288`. Removed real-clock helpers (`BASE_NOW`/`tTime`/`hhmm`); added `dayOf()/hm()/dstamp()` producing mock-clear labels `D<n> HH:MM` (D1–D7). |
| E2 | **Window shape inference** | `sevAt(k,t)`: 2-element `INC` window = linear ramp, 3-element = triangular. The hardcoded `'B'` special case is gone — any key can be either shape. |
| E3 | **Multi-incident objectives** | `objective.inc` may be a string (legacy; amplitude from `o.amp`) **or an object `{incidentKey: amp, …}`**. Effective displacement = MAX over keys of `sevAt(k,t) × ampK`. Legacy string series verified bit-identical. With object form, `o.amp` is inert (left in place as documentation). |
| E4 | **Day-aware chrome** | All timeline-index timestamps use `dstamp()` (9 call sites); `fmtDur()` gained day/hour branches; `drawBands()` now derives bands from `INC` itself and draws D1–D7 day ticks + 6-hour minors; `.dtick/.dlbl` CSS added; `INCMETA` map supplies per-incident label + severity for the scenario banner, and the banner picker generalizes to "strongest currently-open window". |
| E5 | **Week windows in tables** | `WSTEPS` + selectors gain `2d:576` and `7d:2016`. Defaults: Table A `7d`, B `5m`, C `1h`/pay. Reset restores these. |
| E6 | **Speed** | Cycle `1×→4→8→16→32→64` (default 1×). Full-week replay at 64× ≈ 5 s. |
| E7 | **Seeded replay** | All series randomness runs through `mulberry32(keySeed(key))` off `ADEPTIO_SEED`. Each series re-seeds from its own key, so it is independent of generation order. With no `data/log_day*.js` present the engine regenerates a byte-identical week and tags the banner "seeded replay". |
| E8 | **Full-series graphs** | `sparkline(o,w,h,opt)` draws the whole week at every `t`: ghosted (.3) after the cursor, solid before it, with a 1px now-cursor + dot that sweeps during playback. `opt.fluid` stretches to the container; `opt.tint` shades one episode. Used by dock panes, hover card and the incident panel. |
| E9 | **Window clamp** | `clipEps(o,lo,hi)` + `windowScan(t,W)` (memoised per `t\|W`): every windowed figure — events, downtime, first/last seen, worst — comes from ONE walk of `[max(0,t-W+1)..t]` over episodes clipped to it. Table B keeps the episode's true `srcStart` for the "Since" column and marks it `⋯` when it predates the window, but never quotes an end index past `t`. |
| E10 | **Monitors Object Info dock** | `.dock-body{flex:1 1 auto;min-height:0}` (the flex `min-height:auto` default was clipping stacked panes); panes render every objective at natural height; new editable "About this object" section seeded from `ADEPTIO_RCA.nodes[id].desc`, session-only, restored by Reset. |
| E11 | **Incident / RCA panel** | Left slide-in mirroring the dock (`--rcaW:380px`). A delegated handler on `#btables` focuses the node *and* opens the panel keyed to `"<nodeId>.<objective label>"` in `data/rcameta.js`: incident + window stats, customer page + neighbour chips, checks + questions, owner. ✕ or Esc closes. |
| C1 | **Scenario card** | `max-width 280→320px` (the week-arc copy at 280px shadowed the canvas). Fit-scale at 1600/1440/1366/1280 = 0.91/0.83/0.68/0.74. |

Boot cost: 61 objectives × 2016 steps ≈ 30 ms series stitch; DOMContentLoaded ≈ 430 ms. Known future win: downsample the 2016-point table-A sparklines if scrubbing needs >40 fps.

## 3 · Website structure (v1.2.1 site variant)

```
paybill_dashboard_site/
├─ index.html            markup + boot only (loads everything via <link>/<script src> — NO fetch; works over file://)
├─ assets/styles.css     all CSS, verbatim
├─ assets/engine.js      the engine; consumes window.ADEPTIO_DATA + window.ADEPTIO_LOGS
├─ data/manifest.js      window.ADEPTIO_DATA = { NODES (defs, no series), LINKS, INC, INCMETA, KPI def, N, STEP_MIN }
├─ data/log_day1.js …7   OPTIONAL materialised week: window.ADEPTIO_LOGS.d1…d7 = { "<nodeId>.<objIndex>": {vals:[288], stat:[288]}, "KPI": {…} }
├─ README.md             load order, data contract, live-feed wiring, rebuild instructions
└─ build_singlefile.py   re-inlines assets+data → the single-file build product
```

- **Seeded replay (default in the repo)**: no day files shipped; the engine rebuilds the week in-browser from `ADEPTIO_SEED = 20260815` (mulberry32, re-seeded per series key, so order-independent). Every load is identical. `ADEPTIO_MODE = "seeded replay"`, banner-tagged.
- **Materialised week**: the seven day files (release zip / local vault) are a dump of that same seeded output — adding them changes nothing on screen, verified step-for-step. `ADEPTIO_MODE = "frozen-logs"`. Toggle via the one `ADEPTIO-LOGS-START/END` marker pair in `index.html`.
- **Live feed later**: keep the same per-objective `{vals, stat}` shape — replace day files with a poller/SSE writing into `ADEPTIO_LOGS` and the whole UI works unchanged (v1.2 spec §10 promise, now demonstrated).
- Parity: site vs rebuilt single-file — all 62 objective values, statuses and KPI **byte-identical** at t=428/684/1394/1812/2015; zero console errors over `file://`.

## 4 · Retarget rule (updated)

v1.2's "only 5 things to change" still holds, now expressed in the site variant as: **edit `data/manifest.js` (topology + objectives + INC + INCMETA + KPI) and regenerate day logs; never touch `assets/engine.js`.** Copy lives in `index.html`.
